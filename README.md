Analysis pipeline for captions and justifications generated by multimodal LLM agents
conditioned on persona demographics, in an urban-scene perception setting. Compares
persona-conditioned against no-persona annotations across sentiment, semantic similarity,
topic structure, and cross-profile convergence.

## Data

Four annotation corpora, one per annotating model, all following the persona-annotation
protocol of [MLLMs-persona-evaluation](https://github.com/neemiasbsilva/MLLMs-persona-evaluation):
1,200 personas — the 24 profiles of a gender × economic status × political spectrum ×
personality grid, 50 agents each — annotate the same 50 PerceptSent urban scenes, next to
no-persona runs over the same scenes. **The annotating model is the variation.** The Qwen3-VL
corpus is the published [UrbanPersona-60K](https://huggingface.co/datasets/Neemias/UrbanPersona-60K)
release, byte for byte; the Gemma4 corpus and both `T=0` ablation corpora were generated for this
work, in a private extension of the same pipeline that adds a Hugging Face transformers backend.

| `data/<model>/` | Model and backend | Decoding | Persona records | Parse failures | No-persona think / no-think | Generated (UTC) |
| --- | --- | --- | --- | --- | --- | --- |
| `qwen-vl` | Qwen3-VL-8B, `qwen3-vl:8b` via Ollama | `T=0.1` | 59,708 | 292 | 250 / 250 | 2026-02-27 – 2026-03-27; no-persona 2026-05-17 |
| `gemma-4-E4B-it_t01` | `google/gemma-4-E4B-it`, Hugging Face transformers, bf16 | `T=0.1` | 59,999 | 1 | 250 / 250 | 2026-07-21 – 2026-07-22 |
| `qwen-vl-t0` | `Qwen/Qwen3-VL-8B-Instruct`, Hugging Face transformers, bf16 | greedy `T=0.0` | 5,000 | 0 | — / 50 | 2026-07-24 |
| `gemma4-t0` | `google/gemma-4-E4B-it`, Hugging Face transformers, bf16 | greedy `T=0.0` | 5,000 | 0 | — / 50 | 2026-07-24 |

Each `T=0.1` corpus accounts for exactly 60,000 persona × image attempts: every attempt is an
annotation in `annotations_baseline.jsonl` or a record in `annotation_failures.jsonl`, whose JSON
never parsed after three retries — 120,000 in all, over the same 1,200 `persona_id`s and the same
50 `image_id`s. Gemma4's two no-persona runs switch its thinking mode on and off. The `T=0`
corpora hold 100 of the same personas — 50 high-income and 50 low-income, with gender, political
spectrum and personality fixed to Female, Conservative and Analytical — plus one no-persona run.

Each record includes:
1. A predicted sentiment label
2. A caption describing the image
3. One or more perception tags selected from a controlled vocabulary
4. A justification explaining the assigned sentiment

Example record:
```json
{
  "annotation_id": "p<prefix>_img_<image_id>_baseline",
  "persona_id": "<uuid>",
  "image_id": "<perceptsent_image_id>",
  "condition": "baseline",
  "raw_demographics": {
    "gender": "Female",
    "economic_status": "High income",
    "political_spectrum": "Progressive",
    "personality": "Empathetic"
  },
  "predicted_sentiment": "Positive",
  "predicted_perceptions": ["Green/Natural", "Lively"],
  "caption": "A tree-lined street with pedestrians walking on a sunny day.",
  "justification": "This kind of vibrant, green space is exactly what every neighborhood deserves."
}
```

Annotations are organized **per annotating model**, so multiple models coexist and compare
side by side. Each model's corpus lives under `data/<model>/` (e.g. `qwen-vl`,
`gemma-4-E4B-it_t01`); its cached artifacts and figures are namespaced under
`outputs/<model>/` and `figures/<model>/`. The active model is selected via `PERSONA_MODEL`
(default `qwen-vl`).

No corpus is tracked in git: in a fresh clone each `data/<model>/` holds only a `.gitkeep`, and
`./scripts/09_hub.sh pull --groups corpora` fills it (see
[Downloading the datasets](#downloading-the-datasets)). Files required to reproduce the
experiments:

- `data/<model>/annotations_baseline.jsonl`: persona-conditioned annotations.
- `data/<model>/annotations_no_persona_think.jsonl`: no-persona baseline, reasoning enabled.
- `data/<model>/annotations_no_persona_no_think.jsonl`: no-persona baseline, no reasoning.
- `data/<model>/annotation_failures.jsonl`: the persona attempts whose JSON never parsed, with an
  `error` field and empty content fields; published for the attempt count, not read by the analysis.
- `data/qwen-vl-t0/t0_economic_status_*.jsonl`, `data/gemma4-t0/t0_economic_status_*.jsonl`:
  byte-identical copies of the `T=0` corpora under the annotation pipeline's original names, left
  by older checkouts; neither tracked nor published.
- `data/perceptsent-raw/`: original PerceptSent metadata and annotations, for human
  ground-truth agreement (shared across models).

### Downloading the datasets

The corpora, every cached artifact under `outputs/` — including the embedding caches git does not
track — and `figures/` are published on the Hugging Face Hub (see
[Dataset on the Hugging Face Hub](#dataset-on-the-hugging-face-hub)). Pull what the working copy
is missing:

```bash
./scripts/09_hub.sh pull                                   # corpora, outputs, embeddings, figures
./scripts/09_hub.sh pull --groups corpora                  # data/<model>/*.jsonl only (~100 MB)
./scripts/09_hub.sh pull --groups corpora outputs figures  # all but the ~370 MB of embeddings
./scripts/09_hub.sh pull --overwrite                       # also replace local files that differ
```

The dataset stays private until the paper is published, so for now a pull needs a Hugging Face
token with read access to `MInDS-lab-UTFPR` (`uv run hf auth login`); once it is public, no
token is needed. Files download into `hub/downloads/` (gitignored) and are copied to the same
path in the working copy. An existing file is never replaced without `--overwrite`, and then
only when its bytes differ. `rm -rf hub/downloads` reclaims the space afterwards.

## Reproducing the Results

### Full pipeline

`run_experiments.sh` is the single driver. It produces every artifact the paper quotes:

```bash
./run_experiments.sh <model>              # one model: caches, figures, statistics
./run_experiments.sh --all                # every model + cross-model steps + checks + tests
./run_experiments.sh --all --force        # clear caches and recompute from scratch
./run_experiments.sh --all --skip-pipeline  # reuse cached embeddings/similarities/topics
```

`--all` chains the per-experiment scripts in dependency order, then checks `paper.tex`'s
statistics table against the generated artifact and runs the regression tests.

Artifacts to quote in `paper.tex`:

| Artifact | Used for |
| --- | --- |
| `outputs/within_cross_combined_table.tex` | Appendix E table (pasted between the generated-table markers) |
| `outputs/cross_model_correlation.csv` | Table 2 |
| `outputs/<model>/within_cross_significance.csv` | Section 4.2 effects |
| `outputs/<model>/within_cross_modality_contrast.csv` | justification-minus-caption contrasts |
| `outputs/<model>/matched_factorial_modality_contrast.csv` | matched justification-minus-caption contrasts |
| `outputs/t0_ablation_table.tex` | Appendix D table |
| `figures/<model>/`, `figures/` | figures |

`paper.tex` itself is gitignored: it lives here so results can be written into it for
submission, and is never committed.

`outputs/<model>/caption_embeddings.npy` and `justification_embeddings.npy` (~88 MB each)
are gitignored like the corpora, and regenerate on the first run of
`./run_experiments.sh <model>`, or come back with `./scripts/09_hub.sh pull --groups embeddings`.
Every smaller cache in `outputs/<model>/` is committed, so
statistics and figures rebuild without re-encoding.

### Per-experiment scripts

Every experiment has its own entry point under `scripts/`, so any single result reproduces
without rerunning the whole pipeline. Each one takes `--help`; the experiment scripts log to
`outputs/<model>/logs/` and list the artifacts they produced.

| Script | What it runs | Main artifacts |
| --- | --- | --- |
| `./scripts/01_pipeline.sh <model> [--force]` | notebooks in dependency order (EDA → embeddings/similarity → no-persona → BERTopic → convergence) plus the per-model figures | `outputs/<model>/` caches, `figures/<model>/` |
| `./scripts/02_paired_statistics.sh <model> [--check-paper]` | paired Wilcoxon signed-rank tests, BCa intervals, sign-test sensitivity, BH correction | `within_cross_significance.csv`, `within_cross_modality_contrast.csv`, `within_cross_complete_image_sensitivity.csv`, `outputs/within_cross_combined_table.tex` |
| `./scripts/03_t0_ablation.sh` | decoding-sensitivity ablation at `T=0` (Appendix D) | `outputs/<model>-t0/t0_econ_summary.csv`, `outputs/t0_ablation_table.tex`, `figures/fig_t0_ablation.pdf` |
| `./scripts/04_cross_model_correlation.sh` | agreement between the two models' inter-profile matrices (Table 2) | `outputs/cross_model_correlation.csv` |
| `./scripts/05_summary_figures.sh` | cross-model summary figures and annotated backup matrices | `figures/fig_persona_effect_summary.pdf`, `figures/fig_topic_contrasts.pdf` |
| `./scripts/06_tests.sh` | regression tests over the statistical artifacts | pass/fail |
| `./scripts/07_lint.sh [--fix]` | `ruff format`, `ruff check`, `check_style` (no comments, 500-line limit), `mypy --strict` | pass/fail |
| `./scripts/08_matched_factorial.sh <model> [--check-paper]` | matched-factorial contrast (Appendix F): one persona attribute varied while the other three are held fixed, same image-level inference, plus the matched justification-minus-caption contrast | `matched_factorial_persona_sim.csv`, `matched_factorial_significance.csv`, `matched_factorial_modality_contrast.csv`, `matched_factorial_method.json`, `outputs/matched_factorial_table.tex`, `outputs/matched_factorial_contrast_table.tex` |
| `./scripts/09_hub.sh status\|build\|push [--dry-run] [--prune]\|pull [--groups …] [--overwrite]` | publish `data/`, `outputs/` and `figures/` to the Hugging Face Hub, or pull the published files the working copy is missing | `hub/datasets/` staging tree and card, `hub/upload_state.json`, `hub/downloads/` |

Ordering constraints: `02` needs `01` for the same model; `08` needs `01` and `02` for the
same model; `04`, `05`, `02 --check-paper`, and `08 --check-paper` need **both** paper
models to have been processed first.

`paper.tex` carries **three** generated table blocks, none of which is hand-edited:

| Appendix | Markers | Generated file | Checked by |
| --- | --- | --- | --- |
| E (marginal, primary) | `% BEGIN/END GENERATED PAIRED STATISTICS TABLE` | `outputs/within_cross_combined_table.tex` | `./scripts/02_paired_statistics.sh <model> --check-paper` |
| F (matched-factorial effects, secondary) | `% BEGIN/END GENERATED MATCHED FACTORIAL TABLE` | `outputs/matched_factorial_table.tex` | `./scripts/08_matched_factorial.sh <model> --check-paper` |
| F (matched justification-minus-caption) | `% BEGIN/END GENERATED MATCHED FACTORIAL CONTRAST TABLE` | `outputs/matched_factorial_contrast_table.tex` | `./scripts/08_matched_factorial.sh <model> --check-paper` |

Each block is compared byte-for-byte, so wording or layout changes belong in the generator,
never in `paper.tex`. **Paste all three back after every Overleaf sync** — round-tripping
through Overleaf strips the marker comments, and a stripped marker fails `--check-paper`
outright; the two `--check-paper` runs are what catch a drifted block. The statistical method
behind them — per-image aggregation, paired Wilcoxon signed-rank test, BCa intervals, exact
sign test, Benjamini–Hochberg correction — is specified in the paper's methods section.

`./run_experiments.sh <model> [--force]` remains available as the underlying per-model
pipeline that `scripts/01_pipeline.sh` wraps.

### Individual notebooks

Each notebook can also be executed independently (set `PERSONA_MODEL` to pick the corpus):

```bash
PERSONA_MODEL=qwen-vl uv run jupyter nbconvert --to notebook --execute --inplace \
    --ExecutePreprocessor.timeout=1800 \
    notebooks/03_text_similarity_captions.ipynb
```

Available notebooks:

- `notebooks/01_eda_captions_justifications.ipynb` - descriptive statistics for captions, justifications, sentiments, and perception tags.
- `notebooks/02_sentiment_analysis_justifications.ipynb` - sentiment inference with VADER/RoBERTa and agreement against model-predicted and human labels.
- `notebooks/03_text_similarity_captions.ipynb` - Sentence-BERT embeddings and cosine-similarity analyses for captions and justifications.
- `notebooks/04_topic_modeling_bertopic.ipynb` - BERTopic topic discovery over generated text.
- `notebooks/05_convergence_analysis.ipynb` - convergence tests across persona dimensions and profile groups.

## Dataset on the Hugging Face Hub

The corpora and the analysis outputs are published as
**[MInDS-lab-UTFPR/UrbanPersona-120K-Interpretive](https://huggingface.co/datasets/MInDS-lab-UTFPR/UrbanPersona-120K-Interpretive)**,
path for path as they sit in this repository:

```
UrbanPersona-120K-Interpretive/
├── README.md                 the dataset card, generated from what was staged
├── data/<model>/             annotations_baseline, annotation_failures and the no-persona runs
├── outputs/<model>/          every cached artifact, the two embedding caches included
├── outputs/heatmap_values/   the exact numbers behind every published heatmap
├── outputs/cross_model_correlation.csv
└── figures/, figures/<model>/  PDF and PNG
```

Run logs and LaTeX tables stay here. The PerceptSent images are not redistributed; every record
addresses its scene by `image_id`.

### Loading the dataset

Each condition is a config and each model a split, so a model's corpora share one split name:

| Config | Splits | Records |
| --- | --- | --- |
| `baseline` (default) | `qwen_vl`, `gemma_4_E4B_it_t01` | 59,708, 59,999 |
| `failures` | `qwen_vl`, `gemma_4_E4B_it_t01` | 292, 1 |
| `no_persona_think` | `qwen_vl`, `gemma_4_E4B_it_t01` | 250, 250 |
| `no_persona_no_think` | `qwen_vl`, `gemma_4_E4B_it_t01` | 250, 250 |
| `t0_baseline` | `qwen_vl_t0`, `gemma4_t0` | 5,000, 5,000 |
| `t0_no_persona_no_think` | `qwen_vl_t0`, `gemma4_t0` | 50, 50 |

```python
from datasets import load_dataset  # pip install datasets; not a dependency here

REPO = "MInDS-lab-UTFPR/UrbanPersona-120K-Interpretive"
gemma = load_dataset(REPO, "baseline", split="gemma_4_E4B_it_t01")
greedy = load_dataset(REPO, "t0_baseline", split="qwen_vl_t0")
```

Everything outside the configs is a plain file:

```python
from huggingface_hub import hf_hub_download

table = hf_hub_download(REPO, "outputs/cross_model_correlation.csv", repo_type="dataset")
```

Inside this repository, `./scripts/09_hub.sh pull` puts the files back where the pipeline reads
them (see [Downloading the datasets](#downloading-the-datasets)).
